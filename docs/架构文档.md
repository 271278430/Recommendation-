# 项目架构地图（人话版）

> 一句话：项目分**三层** + 离线工具 + 文档。
> `mastery_store`（底层数据层）← `service`（你的 FastAPI 服务）→ `data`（题库/图谱）。

---

## 0. 全景图

```
Recommend_question/
│
├── mastery_store/     ① 底层数据层：掌握度的存储 + 算法（独立、共享，不依赖任何上层）
├── service/           ② 应用层：你的 FastAPI 服务（遗忘/推题接口）—— 依赖 ①
├── data/              ③ 数据文件：题库 + 知识图谱（被 ① ② 读）
├── tests/             ② 的自动化测试
│
├── scripts/           离线工具：建图/标注/初始化/评估/调参（12 个脚本）
├── docs/              文档（学情建模、接口规范、API 参考等）
├── conftest.py        pytest 配置
├── pyproject.toml     依赖声明
├── run_tests.sh       一键全量测试脚本
```

**依赖方向**：`service` → `mastery_store` → `data`。**反过来不依赖**（底层不知道上层存在）。

## ① `mastery_store/` —— 底层数据层

掌握度的"数据库 + 计算公式"。学生每答一题，这里更新掌握度；推荐/遗忘服务来这里读。

| 文件 | 干什么 | 你需要懂吗 |
|---|---|---|
| `mastery_store.py` | **核心**：连 PostgreSQL 读写掌握度（α,β,m_peak,last_ts）+ 7 步更新流水线 + `forget_decay` 衰减公式 + 所有常量（P、τ 等） | 是（算法心脏） |
| `practice.py` | 做题事件读写：`practice_event` 表（做题历史/错题本/幂等） | 是 |
| `__init__.py` | 包入口：让外面能 `import mastery_store` | 否 |
| `docker-compose.yml` | PG 容器定义（端口 5433） | 否 |
| `init/*.sql` | 建表脚本：student_mastery + practice_event | 否 |
| `scripts/web_app.py` | Flask 调试 UI + 数据加载器（已归档 scripts/） | 否 |

> 你日常只需要知道：**`mastery_store.py` 是掌握度的存储和公式来源**，别的文件是它的工具链，可以忽略。

## ② `service/` —— 你的 FastAPI 服务（重点）

这是你新搭的、分层的企业级结构。**为什么分 `core/svc/api`？** 因为不同职责要分开：`api` 管 HTTP、`svc` 管业务、`core` 管所有接口共用的基础设施。

```
service/
├── main.py            🚪 门口：组装 App（挂中间件、注册路由），只做组装
│
├── core/              🧰 基础设施（所有接口共用，跟具体业务无关）
│   ├── config.py         配置：端口、路径、日志级别（从环境变量读）
│   ├── response.py       统一返回格式 {code,msg,data,trace_id} + 错误码 + 业务异常
│   ├── logging.py        日志 + trace_id
│   ├── middleware.py     中间件：每请求贴 trace_id、兜底所有异常
│   ├── kp_registry.py    kp_id ↔ kp_idx ↔ kp_name 唯一映射（启动时构建）
│   └── deps.py           启动与依赖注入
│
├── svc/               🧠 业务逻辑（算东西，不碰 HTTP）
│   ├── forget.py         遗忘衰减（只读，数学与 mastery_store 一致）
│   ├── recommend.py      粗召回（IRT 公式 + ZPD 过滤）
│   ├── learning.py       学情组装（掌握度 + 历史 + 图谱边）
│   ├── practice.py       做题序列 + 答题更新
│   ├── knowledge_graph.py 图谱边（先修/共现，向量化）
│   └── question_bank.py  题库索引（懒加载倒排）
│
└── api/               🌐 HTTP 路由（接请求、派活，不做计算）
    ├── mastery.py        GET  /students/{id}/mastery
    ├── practice.py       GET|POST /students/{id}/practice-events
    ├── recommend.py      POST /students/{id}/recommendations
    ├── student.py        GET /students + GET /students/{id}/learning-status
    └── meta.py           GET /knowledge-points /knowledge-graph/edges
```

**记忆口诀**：
- `api/` = 前台（接客、派单）
- `svc/` = 后厨（真正做菜：算衰减、召回、学情组装）
- `core/` = 物业水电（每家店都要用，跟做什么菜无关）
- `main.py` = 大门（把店开起来，不干厨子的活）

## 一个请求是怎么走完这些文件的

学生调 `GET /api/v1/students/123/mastery?kp_ids=J03...`：

```
1. main.py          门开了，请求进来
2. core/middleware   贴 trace_id 号牌
3. api/mastery.py    前台接单：从路径取 student_id、query 取 kp_ids
4. svc/forget.py     后厨：调 mastery_store 取 α,β,last_ts
5. mastery_store     查 PG 拿原始状态
6. svc/forget.py      套衰减公式，算出 m=0.6272
7. api/mastery.py    装进 {code,msg,data,trace_id}
8. core/middleware   响应头加 X-Trace-Id
9. main.py           返回
```

**任何一层只干自己的事**。
