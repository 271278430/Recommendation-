# 推荐服务接口文档

> 五个接口：遗忘掌握度（只读）、学情查询（只读）、做题序列（只读）、粗召回（只读）、答题更新（写入）。
> 统一规范：KP 标识用 `kp_id`（题库唯一 id），响应 `{code, msg, data, trace_id}` + 响应头 `X-Trace-Id`。

---

## 0. 共同约定

所有接口共享以下规范，不重复说明：

| 项 | 规范 |
|---|---|
| 请求 | `POST` + `Content-Type: application/json`，请求体为 JSON |
| 响应 | 统一外层 `{code, msg, data, trace_id}`；成功 `code=0`，`data` 为业务数据；失败 `data` 为 null 或错误详情 |
| 追踪 | 响应头 `X-Trace-Id` 与响应体 `trace_id` 同值，用于排障定位 |
| KP 标识 | `kp_id`（如 `J030004000200080003`），题库唯一 id，所有接口统一使用 |
| 时间 | ISO 8601（含时区），如 `2026-07-16T09:00:00+00:00` |
| 错误码 | `40401` scope 不存在 / `40403` kp_id 不存在 / `40404` 题目不存在 / `40002` 题目无知识点标签 / `40001` 参数非法 / `50001` 内部错误 |

---

## 0.1 共用基础设施

所有接口复用以下组件（启动时构建，请求时复用）：

| 组件 | 作用 |
|---|---|
| `KPRegistry` | kp_id ↔ 内部 idx 的唯一权威转换，所有接口通过它做知识点标识映射 |
| `TraceIdMiddleware` | 每请求生成 trace_id + 兜底所有异常为统一错误响应 |
| `ApiResponse` / `BizError` | 统一响应封装 + 业务异常 |

## 1. 遗忘掌握度 — `POST /api/v1/mastery/forget`

### 功能

获取学生每个知识点**经过时间遗忘后的当前掌握度**。数据库存的是上次练习时刻的快照（可能已过期），本接口按"现在距上次练习的时间差"套用遗忘衰减公式，返回衰减后的真实掌握度。**纯只读，不改库。**

用途：推题时判断学生当前水平、学情展示、计算难度匹配。

### 输入

传入学生 ID + 想查的知识点（不传则查全部 612 个）。

```json
{"student_id": 888888, "kp_ids": ["J030004000200080003"]}
```

| 字段 | 类型 | 必填 | 说明 |
|---|:--:|---|
| `student_id` | int | 是 | 学生 ID |
| `kp_ids` | string[] | 否 | 知识点 id 列表；不传 = 该学生全部 612 个知识点 |

### 输出

返回每个知识点的衰减后状态。核心是 `m`（遗忘后掌握度），辅助有 `m_peak`（峰值）、`N`（证据量/置信度）、`last_ts`（上次练习时间）、`days_since`（距今天数）、`has_data`（是否练过）。

```json
{
  "code": 0, "msg": "ok",
  "data": {
    "student_id": 888888,
    "now": "2026-07-15T05:36:13",
    "items": [
      {
        "kp_name": "正数和负数",
        "kp_id": "J0300010001000100010006",
        "m": 0.6272,
        "m_peak": 0.6849,
        "N": 7.32,
        "last_ts": "2026-07-08T09:44:28",
        "days_since": 6.83,
        "has_data": true
      }
    ]
  },
  "trace_id": "43a2031ce77d"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `kp_name` | string | 知识点名称 |
| `kp_id` | string/null | 统一标识（少数图谱独有节点为 null） |
| `m` | float | **遗忘后掌握度**（核心输出，∈(0,1)；0.5=不确定，越低越薄弱） |
| `m_peak` | float | 遗忘后历史峰值（曾达到的最高水平，缓慢回落中） |
| `N` | float | 遗忘后总证据量（置信度；越大判断越稳，≤100） |
| `last_ts` | string/null | 上次练习时间；null=从未练习过 |
| `days_since` | float | 距上次练习的天数 |
| `has_data` | bool | 是否有练习记录（`last_ts≠null` 且 `N>4`） |

### 错误

| 场景 | HTTP | code |
|---|---|---|
| kp_id 不存在 | 404 | 40403 |

### 实现调用链

```
路由  forget_endpoint          api/mastery.py     校验 kp_id、组装响应
  └→ 业务 get_decayed          svc/forget.py      读存储 + 对每个 KP 衰减
        ├ decayed_for_kp       svc/forget.py      单 KP 只读衰减（核心纯函数，复刻 forget_decay）
        └ now_utc_naive       svc/forget.py      取当前时间
  └→ 数据 get_state            mastery_store      从 PG 读 α,β,m_peak,last_ts 数组
```

## 2. 学情查询 — `POST /api/v1/student/learning-status`

### 功能

一次调用返回学生的**完整学情报告**：掌握度概览（各知识点水平 + 等级分布 + 薄弱/久未练高亮）+ 做题历史（最近做题明细 + 正确率/总题数）+ 可选的知识点关系图谱边。给前端学情看板/学生报告用。

`include_graph=true` 时额外返回范围内的知识点先修/共现关系边，前端据此渲染可视化学情图谱。

### 输入

传入学生 ID + 查询范围（按模块或指定知识点）+ 可选控制参数（时间窗、明细条数、是否要图谱边）。

```json
{
  "student_id": 888888,
  "scope_type": "kp_ids",
  "scope_value": ["J030004000200080003"],
  "aspects": ["mastery", "history"],
  "history_days": 30,
  "history_limit": 20,
  "mastery_detail": true,
  "include_graph": false
}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|:--:|:--:|---|
| `student_id` | int | 是 | - | 学生 ID |
| `scope_type` | enum | 是 | - | `module`（按模块名）/ `kp_ids`（按知识点 id 列表） |
| `scope_value` | string 或 string数组 | 是 | - | module 时填模块名；kp_ids 时填知识点 id 列表 |
| `aspects` | string[] | 否 | `["mastery","history"]` | 要返回哪些部分，可只要 mastery 或只要 history |
| `history_days` | int | 否 | 30 | 做题统计的时间窗（最近 N 天，1~365） |
| `history_limit` | int | 否 | 20 | 做题明细最多返回几条（1~200） |
| `mastery_detail` | bool | 否 | true | false 时只返回汇总统计、不返回每个知识点的明细 |
| `include_graph` | bool | 否 | false | true 时额外返回知识点关系边（先修/共现），供渲染图谱 |
| `edge_types` | string[] | 否 | `["prereq","cooc"]` | 要哪些关系边 |
| `cooc_min_weight` | float | 否 | 0.25 | 共现边强度下限（NPMI，-1~1），低于此值的边丢弃 |

### 输出

返回三部分（`aspects` 控制返回哪些）+ 可选的图谱边：

- **mastery**：掌握度概览。`summary` 是汇总统计（平均掌握度、各等级人数、最薄弱/最久未练 top5），`items` 是每个知识点的明细（掌握度 + 等级 + 做题数 + 最近错题数）。
- **history**：做题历史。`summary` 是汇总（总题数、正确率、最近活跃时间），`events` 是最近做题明细列表。
- **graph**（仅 `include_graph=true`）：知识点关系边列表。每条边连接两个知识点，标注是先修（有向）还是共现（无向）。掌握度数据已在 mastery 里，graph 只附加关系。

```json
{
  "code": 0, "msg": "ok",
  "data": {
    "student_id": 888888,
    "now": "2026-07-15T05:36:13",
    "scope": {"type": "kp_ids", "value": ["J030004..."], "kp_count": 1},
    "mastery": {
      "summary": {
        "total_kp": 1, "has_data_kp": 1, "avg_m": 0.63,
        "level_counts": {"未接触":0, "补弱":0, "巩固":1, "变式":0, "进阶":0},
        "weakest": [{"kp_id":"...", "kp_name":"勾股定理", "m":0.21}],
        "stalest": [{"kp_id":"...", "kp_name":"勾股定理", "days_since":42}]
      },
      "items": [
        {
          "kp_id": "J030004000200080003", "kp_name": "勾股定理",
          "m": 0.6272, "level": "巩固", "N": 7.32,
          "has_data": true, "days_since": 6.8,
          "practice_count": 8, "recent_wrong_count": 2
        }
      ]
    },
    "history": {
      "summary": {
        "total_answered": 120, "accuracy": 0.72,
        "last_active_ts": "2026-07-08T09:44:28"
      },
      "events": [
        {
          "question_id": "exam_20251016_11-14",
          "ts": "2025-10-16T09:00:00", "ques_type": "单选题", "difficulty": null,
          "score": 1.0, "is_wrong": false,
          "kp_ids": ["J030004000200080003", "J030004000200090002"]
        }
      ]
    },
    "graph": {
      "edges": [
        {"from": "J03000300010004", "to": "J030003", "type": "prereq", "subtype": "间"},
        {"from": "J0300030003", "to": "J03000300030001", "type": "cooc", "weight": 0.4039}
      ]
    }
  },
  "trace_id": "43a2031ce77d"
}
```

**mastery 字段说明**

| 字段 | 说明 |
|---|---|
| `summary.avg_m` | 范围内平均掌握度（仅计入有练习记录的知识点） |
| `summary.level_counts` | 各掌握度等级的知识点数量（未接触/补弱/巩固/变式/进阶） |
| `summary.weakest[]` | 掌握度最低的 top5 知识点（`kp_id/kp_name/m`） |
| `summary.stalest[]` | 最久没练的 top5 知识点（`kp_id/kp_name/days_since`） |
| `items[].m` / `level` | 该知识点遗忘后掌握度 / 对应等级 |
| `items[].practice_count` | 该知识点历史做题总数（不限时间窗） |
| `items[].recent_wrong_count` | 该知识点在 `history_days` 时间窗内的错题数 |

**history 字段说明**

| 字段 | 说明 |
|---|---|
| `summary.total_answered` | 范围+时间窗内的总做题数 |
| `summary.accuracy` | 正确率（正确数/总数） |
| `summary.last_active_ts` | 范围+时间窗内最近一次做题时间 |
| `events[]` | 最近做题明细列表，每条含题目 ID、时间、题型、难度、得分率、对错、关联知识点 |

**graph 字段说明**（仅 `include_graph=true` 时返回）

| 字段 | 说明 |
|---|---|
| `edges[].from` / `to` | 边两端的知识点 `kp_id`（与 mastery.items 的 kp_id 对应） |
| `edges[].type` | `prereq`（先修，有向：from 是 to 的前置知识点）/ `cooc`（共现，无向） |
| `edges[].subtype` | 仅 prereq：`内`（直接前置）/ `间`（间接前置） |
| `edges[].weight` | 仅 cooc：NPMI 共现强度 ∈ [-1,1]，越大表示两个知识点越常一起考 |

> graph 边是**静态知识图谱数据**（所有学生相同），只含两端都在查询范围内的边。掌握度（节点数据）已在 mastery 里，graph 只附加知识点间的关系。

### 错误

| 场景 | HTTP | code |
|---|---|---|
| scope_value 无效（模块名不存在或 kp_id 全部无效） | 404 | 40401 |

### 实现调用链

```
路由  learning_status_endpoint  api/student.py     解析 scope、组装响应
  └→ 业务 learning_status        svc/learning.py    主入口：组装 mastery + history
        ├ resolve_scope          svc/learning.py    scope → KP 列表（module/kp_ids）
        ├ _mastery_part          svc/learning.py    掌握度概览 + 等级分布 + 薄弱/久未练
        │   ├ get_decayed        svc/forget.py      复用遗忘衰减（每个 KP 的 m/level）
        │   ├ get_kp_stats       practice           每知识点做题数 + 最近错题数
        │   └ level_of           svc/learning.py    m → 等级（补弱/巩固/…）
        └ _history_part          svc/learning.py    做题汇总 + 事件流
            ├ get_history_summary practice           总题数/正确率/最近活跃
            └ get_student_events  practice           最近做题明细
        └ get_edges（include_graph=true 时） svc/knowledge_graph.py  附加先修/共现边
  └→ 数据 mastery_store + practice                  掌握度（student_mastery）+ 做题历史（practice_event）
```

## 3. 做题序列 — `POST /api/v1/practice/kp-sequence`

### 功能

查某学生在**某一个**知识点上的完整做题历史（按时间倒序）。学情查询返回的是多知识点的"概览 + 最近几条"，本接口是"钻进一个知识点看它的全部做题记录"。用于下钻查看、错题本、以题推题选锚点。

### 输入

传入学生 ID + 一个知识点 ID + 可选过滤（最多几条、是否只要错题）。

```json
{"student_id": 888888, "kp_id": "J030004000200080003", "limit": 50, "wrong_only": false}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|:--:|:--:|---|
| `student_id` | int | 是 | - | 学生 ID |
| `kp_id` | string | 是 | - | 要查看的知识点 id |
| `limit` | int | 否 | 50 | 最多返回几条（1~500） |
| `wrong_only` | bool | 否 | false | true=只返回错题（用于错题本/选错题锚点） |

### 输出

返回该知识点上的做题事件列表（按时间倒序，最近在前）。每条事件记录：做了哪道题、什么时间、什么题型/难度、得分多少、对还是错、这道题考了哪些知识点。

```json
{
  "code": 0, "msg": "ok",
  "data": {
    "student_id": 888888,
    "kp_id": "J030004000200080003",
    "count": 1,
    "events": [
      {
        "question_id": "exam_20251016_1",
        "ts": "2025-10-16T09:00:00",
        "ques_type": "单选题", "difficulty": null,
        "score": 1.0, "is_wrong": false,
        "kp_ids": ["J030004000200080003"]
      }
    ]
  },
  "trace_id": "13091081d272"
}
```

| 字段 | 说明 |
|---|---|
| `count` | 实际返回的条数（可能被 limit 或 wrong_only 截断） |
| `events[].question_id` | 题目标识 |
| `events[].ts` | 答题时间（按时间倒序排列） |
| `events[].ques_type` | 题型（单选题/填空题/简答题/…） |
| `events[].difficulty` | 难度档（容易/较易/适中/较难/困难，可能为 null） |
| `events[].score` | 得分率 ∈ [0,1] |
| `events[].is_wrong` | 是否判错（score < 0.5） |
| `events[].kp_ids` | 这道题考察的所有知识点 id（包含当前查询的 kp_id，可能还有其他） |

### 错误

| 场景 | HTTP | code |
|---|---|---|
| kp_id 不存在 | 404 | 40403 |

### 实现调用链

```
路由  kp_sequence_endpoint      api/practice.py    校验 kp_id、组装响应
  └→ 业务 kp_sequence           svc/practice.py    取事件 + 整形（时间转 ISO）
  └→ 数据 get_kp_sequence       practice           按 kp_id 过滤 practice_event，按时间倒序
```

## 4. 答题更新 — `POST /api/v1/practice/submit-answer`

### 功能

学生答完一道题后调用——**更新掌握度**（执行 7 步更新流水线：遗忘衰减 → IRT 预测 → 误差计算 → 重学加速 → 加权融合 → 持久化）+ **写做题记录**（practice_event 追加一行）。返回受影响知识点的掌握度 before→after 变化和等级变化。

是学情系统的**唯一写入入口**：所有掌握度变化和做题记录增长都从这里进。其余三个接口都是只读，消费这里更新后的数据。

### 输入

调用方只需传 3 个核心参数：谁（student_id）做了哪道题（question_id）得了多少分（score）。题目的属性（考哪些知识点、什么题型、什么难度）由服务端从题库查，调用方不用管。

```json
{"student_id": 888888, "question_id": "3b8651d6-...", "score": 1.0, "source": "homework"}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|:--:|:--:|---|
| `student_id` | int | 是 | - | 学生 ID |
| `question_id` | string | 是 | - | 题目 ID（题库 `_id` 字段） |
| `score` | float | 是 | - | 得分率 [0,1]；选择题 0 或 1，解答题=实际得分/满分 |
| `source` | string | 否 | homework | 答题来源：exam（考试）/ homework（作业）/ classwork（课堂） |
| `ts` | string | 否 | now | 答题时间（ISO 8601），不传则用服务器当前时间 |
| `equal_weights` | bool | 否 | false | 多知识点权重控制：true=强制等权；false=自动查题库权重文件，无则等权兜底 |

> **多知识点权重三级兼容**：一道题考多个知识点时，每个知识点分到多少更新权重？三级优先级：
> 1. `equal_weights=true` → 强制等权（每个知识点平分）
> 2. `equal_weights=false`（默认）→ 查 `question_kp_weights.jsonl`（8367 道题有精确权重）
> 3. 都没有 → 等权兜底

### 输出

返回这道题影响了哪些知识点，每个知识点的掌握度变化（答题前 → 答题后 → 变化量）和等级变化。同时回显题目属性（让调用方确认服务端查到的题目信息）。

```json
{
  "code": 0, "msg": "ok",
  "data": {
    "student_id": 888888,
    "question_id": "3b8651d6-...",
    "score": 1.0,
    "is_wrong": false,
    "question": {"ques_type": "简答题", "difficulty": "容易", "kp_ids": ["J03000200040002"]},
    "updated_kps": [
      {"kp_id": "J03000200040002", "kp_name": "一次不等式（组）的应用",
       "m_before": 0.5000, "m_after": 0.5296, "delta": 0.0296,
       "level_before": "未接触", "level_after": "巩固"}
    ]
  },
  "trace_id": "5f51b6a87e00"
}
```

| 字段 | 说明 |
|---|---|
| `is_wrong` | 是否判错（score < 0.5） |
| `question` | 服务端从题库查到的题目属性回显：题型、难度、考察的知识点列表 |
| `updated_kps[].m_before` | 答题前的掌握度（经遗忘衰减，= 学生当时看到的值） |
| `updated_kps[].m_after` | 答题后的掌握度（7 步流水线更新后的新值） |
| `updated_kps[].delta` | 掌握度变化量（正=进步，负=退步；答对应正、答错应负） |
| `updated_kps[].level_before` | 答题前的掌握度等级（未接触/补弱/巩固/变式/进阶） |
| `updated_kps[].level_after` | 答题后的等级（可能跨级，如 未接触→巩固） |

> `m_before` 是"衰减后"的值（学生当时看到的），`m_after` 是更新后的存储值。delta 反映的是**这次答题**带来的变化（不含遗忘，因为 before 已含衰减）。

### 错误

| 场景 | HTTP | code |
|---|---|---|
| 题目不存在（题库里没这道题） | 404 | 40404 |
| 题目无知识点标签（无法更新掌握度） | 400 | 40002 |
| 题目知识点无法解析（kp_id 全部映射失败） | 400 | 40001 |

### 实现调用链


## 5. 粗召回 — `POST /api/v1/recommend/recall`

### 功能

推荐流程的第一阶段：给定学生 + 知识点范围，按 **IRT 预测答对率 `p∈[0.30, 0.80]`** 召回所有难度匹配的候选题目。返回每个知识点的候选题库（不限数量、不去重、不排除已做题）。

这是推荐系统的"召回层"——广、全、不截断。后续"精排"（排序/去重/排除已做题/比例控制/截断）是独立阶段。

ZPD 定义：`p = g + (1-g)·σ(k·(m-d))`，其中 m 是学生衰减后掌握度、d 是题目难度、g 是题型猜测率、k=5 是区分度。比 `|m-d|≤阈值` 更有教学含义，且自动考虑题型猜测率和题目区分度。

### 输入

前端传入学生 ID + 知识点范围。后端据此查掌握度、筛候选，不替调用方决定"选哪个学生"或"选哪些知识点"。

```json
{"student_id": 888888, "kp_ids": ["J030004000200080003", "J030004000200090002"]}
```

| 字段 | 类型 | 必填 | 说明 |
|---|:--:|---|
| `student_id` | int | 是 | 学生 ID（后端据此查该学生的掌握度） |
| `kp_ids` | string[] | 是 | 要推题的知识点 id 列表（前端/老师选定） |

### 输出

返回每个知识点的候选题库。每个知识点带：方向（补弱/巩固/…）、衰减后掌握度 m、是否练过、召回的题目列表（按 `p` 降序，学生最可能做对的在前）。

```json
{
  "code": 0, "msg": "ok",
  "data": {
    "student_id": 888888,
    "groups": [
      {
        "kp_id": "J030004000200080003",
        "kp_name": "勾股定理",
        "m": 0.4800,
        "has_data": true,
        "direction": "巩固",
        "question_count": 12,
        "questions": [
          {
            "question_id": "841e4358-dc1a-4123-9abc-def012345678",
            "ques_type": "单选题",
            "difficulty": "较易",
            "d": 0.35,
            "p": 0.74,
            "kp_ids": ["J030004000200080003"]
          }
        ]
      }
    ],
    "empty_kps": [
      {"kp_id": "J03000500010001", "kp_name": "投影", "reason": "题库中该知识点无 p∈[0.30,0.80] 的题"}
    ]
  },
  "trace_id": "a1b2c3d4e5f6"
}
```

| 字段 | 说明 |
|---|---|
| `groups[].kp_id` / `kp_name` | 知识点 id / 名 |
| `groups[].m` | 该学生该知识点的衰减后掌握度（决定难度匹配的基准） |
| `groups[].has_data` | 是否有练习记录（false 时 m=0.5 是先验值） |
| `groups[].direction` | 推荐方向：补弱/巩固/变式/进阶（由 m 按阈值分类） |
| `groups[].question_count` | 该知识点召回的候选题数（**不限上限**，粗召回全量返回） |
| `groups[].questions[]` | 候选题目列表，按 `p` 降序 |
| `questions[].d` | 难度数值（`DIFF_MAP[difficulty]`，与掌握度标定同源） |
| `questions[].p` | IRT 预测答对率（所有候选 p∈[0.30, 0.80]） |
| `questions[].kp_ids` | 这道题考察的所有知识点（多知识点题会列出多个） |
| `empty_kps[]` | 召回为空的知识点（前端据此弹窗提示） |

> **不设每知识点上限**、**不做去重**、**不排除已做题**——这三件事都留给精排阶段。
