# 接口数据规范

> 所有接口必须遵循的统一格式约定。目的：**让接口能串成流程**——上一步的输出直接是下一步的输入，无需翻译。
>
> 新增任何接口前先读本文；不符合规范的接口不予合并。

---

## 1. 知识点标识：统一用 `kp_id`

**这是最重要的约定。** 所有 API 输入/输出里，知识点一律用 `kp_id`（题库唯一 id，形如 `J030004000200080003`）标识。

### 三套标识的分工

| 标识 | 用在哪 | 谁认 |
|---|---|---|
| **`kp_id`** | **API 输入/输出（唯一规范）** | 题库 / 前端 / 外部 |
| `kp_idx` | 内部存储/计算（mastery_store 索引 0..611） | 仅后端内部 |
| `kp_name` | 人读展示 | 仅显示 |

### 唯一映射源：`KPRegistry`（service/core/kp_registry.py）

启动时构建一次，是 `kp_id ↔ kp_idx ↔ kp_name` 的**唯一权威映射**。所有转换走它，不各写一份：

| 转换 | 方法 |
|---|---|
| kp_id → kp_idx | `reg.kp_id_to_idx(kp_id)` |
| kp_idx → kp_id | `reg.idx_to_kp_id(idx)` |
| kp_id 列表 → kp_idx 列表 | `reg.resolve(kp_ids)` → (idxs, invalid) |
| kp_id → 名称 | `reg.kp_id_to_name(kp_id)` |

### 流程衔接规则

- 上下游接口之间的 KP 一律用 `kp_id` 传递：`学情.items[].kp_id` → `推题入参 kp_ids`、`图谱节点 kp_id` → `forget/sequence 入参 kp_id`。
- 内部（service/data 层）可转成 `kp_idx` 算掌握度，但**回到 API 边界必须用 `kp_id`**。
- 极少数 KPs（612 中约 12 个）题库无对应 `kp_id`（没有题考它），其 `kp_id` 为 `null`——合法，下游需容忍。

## 2. 统一响应封装

所有接口返回统一外层：

```json
{"code": 0, "msg": "ok", "data": { ... }, "trace_id": "43a2031ce77d"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 0=成功；非 0 见错误码 |
| `msg` | string | 状态信息 |
| `data` | object/array/null | 业务数据；失败时可能为 null 或带错误细节 |
| `trace_id` | string | 请求追踪 ID；同时通过响应头 `X-Trace-Id` 回传 |

---

## 3. 错误格式

业务错误抛 `BizError(code, msg, http_status, data)`，由全局处理器转成统一结构：

```json
{"code": 40403, "msg": "部分 kp_id 不存在", "data": {"invalid_kp_ids": ["FAKE"]}, "trace_id": "..."}
```

错误码表（`ErrorCode`）：

| code | HTTP | 含义 |
|---|:--:|---|
| 0 | 200 | 成功 |
| 40001 | 400 | 参数缺失/非法 |
| 40101 | 401 | 未鉴权 |
| 40301 | 403 | 无权限 |
| 40401 | 404 | scope 不存在 |
| 40402 | 404 | 学生不存在 |
| 40403 | 404 | kp_id 不存在 |
| 40404 | 404 | 范围/资源无效 |
| 50001 | 500 | 内部错误 |

## 4. 通用字段约定

| 项 | 约定 |
|---|---|
| 命名 | `snake_case`（如 `student_id`、`kp_ids`、`days_since`） |
| 时间 | ISO 8601 UTC 字符串（如 `2026-07-15T05:36:13`） |
| 缺值 | 用 `null`，不省略字段 |
| 数组 | 知识点集合用 `kp_id[]`；一题多知识点也用数组 |
| 布尔 | `has_data` / `is_wrong` 等，小写 |
| 浮点 | 掌握度/得分率等保留 4 位小数 |

## 5. 范围 scope 格式

需要"按范围圈知识点"的接口（图谱、学情、推题 step1）统一用：

```json
{"scope_type": "module", "scope_value": "六、三角形与全等"}
```

| `scope_type` | `scope_value` | 状态 |
|---|---|---|
| `module` | 模块名（17 个） | ✅ 可用 |
| `kp_ids` | 知识点 id 列表 | ✅ 可用 |
| `chapter` / `section` / `topic` | 章/节/专题 | ⏳ 待课程数据 |

---

## 6. 掌握度等级 `level`

由 `m`（遗忘后掌握度）按固定阈值分类，所有接口一致：

| level | 条件 |
|---|---|
| `未接触` | `has_data = false` |
| `补弱` | `m < 0.45` |
| `巩固` | `0.45 ≤ m < 0.65` |
| `变式` | `0.65 ≤ m < 0.80` |
| `进阶` | `m ≥ 0.80` |

> `level` 是后端算的分类结果（语义数据），不是展示用颜色。颜色由前端决定。

## 7. 接口清单与标识一致性

| 接口 | 输入 KP | 输出 KP | 状态 |
|---|---|---|---|
| `POST /mastery/forget` | `kp_id[]` | `kp_id`（每 item） | ✅ 已统一 |
| `POST /mastery/graph` | scope | `kp_id`（节点+边） | ⏳ 待改（现用 kp_idx） |
| `POST /student/learning-status` | scope | `kp_id`（items+events） | ⏳ 待改（events 现用 kp_name） |
| `POST /practice/kp-sequence` | `kp_id` | events 含 `kp_id[]` | ⏳ 待建 |

**目标**：所有"输出 KP"列都是 `kp_id`，上下游天然衔接。
